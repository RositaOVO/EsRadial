# 玩家轮盘布局

需要 EsRadial **0.3.0**。Espetro、EsPoints 及其他使用 EsRadial 的菜单都会自动读取客户端布局。

## 游戏内拖动

1. 正常打开想调整的轮盘，包括需要调整的子菜单，然后按 **F6**。
2. 进入编辑界面后可以松开原来的轮盘键；编辑期间不执行任何菜单动作。
3. 按住左键拖动图标所在扇区，松到另一个扇区上，改变顺序。空槽用小空心圆标识，也可以拖动。
4. 拖动分界线（外缘有黄色点）调整两侧扇区大小；默认吸附到最近的30°或45°倍数，滚轮转到下一个吸附位置。**Tab** 切换混合、30°、45°和自由模式；自由模式滚轮每格5°。
5. **Enter** 保存并退出。**Esc** 取消并退出。**R** 恢复当前菜单默认布局，再按 Enter 才保存。

拖动扇区会保留它的角度大小并移动到目标顺序位置。拖动分界线保持两个相邻扇区总角度不变，
防止重叠或缩为零。拖到圆环之外再松开会撤销该次移动。
死亡、离开当前维度、断线或失去窗口焦点会取消尚未保存的编辑。

## 修改配置文件

文件在**客户端游戏目录**的 `config/esradial/layouts.json`，不是地图服务器目录。
首次打开每个菜单时会自动写入该菜单的默认布局和稳定按钮 ID。
手工修改后关闭、重新打开轮盘即可读取；无需重启游戏。编辑界面保存也写入同一个文件。

文件结构：

```json
{
  "version": 1,
  "menus": {
    "example:wheel": [
      {
        "innerRadius": 44,
        "outerRadius": 96,
        "sectors": [
          { "slot": "example.attack", "start": 330, "sweep": 60 },
          { "slot": null, "start": 30, "sweep": 40 },
          { "slot": "example.defend", "start": 70, "sweep": 90 },
          { "slot": null, "start": 160, "sweep": 170 }
        ]
      }
    ]
  }
}
```

上面是说明结构的示例；实际请编辑游戏自动导出的菜单名称和按钮 ID。

| 字段 | 含义 |
| --- | --- |
| `menus` 下的键 | 模组提供的菜单 ID；不同菜单分别保存 |
| 每个菜单的数组 | 同一个菜单不同选项集合的布局，例如不同权限或不同补给分页 |
| `innerRadius` / `outerRadius` | GUI 逻辑像素半径；`0 ≤ 内半径 < 外半径 ≤ 512` |
| `slot` | 稳定按钮 ID；`null` 表示空槽，空槽可以有多块 |
| `start` | 起始角度，从正上方起顺时针计算；负角度、跨零度都支持 |
| `sweep` | 扇区角度，必须大于 0、不超过 360 |

所有真实按钮必须恰好出现一次；扇区不能重叠。未覆盖角度自动留空。
用 `start` 调位置，用 `sweep` 调大小；可增加、移动、缩小或删除 `slot: null` 的条目。
配置只改变呈现和命中位置，不改变按钮含义、权限、服务端冷却或网络请求。

按**按钮 ID 集合**选择 profile，不依赖模组数组中的索引或排列顺序。
某项暂时不可用但仍在菜单中时保留布局；角色、目录或分页改变了选项集合时会创建独立默认 profile，
原集合再次出现时恢复其已保存布局。

JSON 语法错误、重叠、重复按钮或非法半径会在日志中报告；无法应用时使用默认轮盘。
不会自动覆盖坏文件。语法错误需要先修好才能从编辑器保存；几何错误可在编辑器中重排或恢复默认后保存。
保存使用临时文件和原子替换，保存前会重新读取文件，以保留对其他菜单的手动修改。

## 模组接入

`open`、`navigate`、`replace` 和 `back` 会自动应用配置。模组不需要自己读文件。
保持菜单 ID 和按钮 ID 稳定；不要用按钮 ID 承载余额、图标颜色或其他每帧变化的数据。
`RadialMenuClientApi.editCurrentLayout()` 也可以从客户端线程调用，返回是否成功进入编辑器。
编辑器会先结束动作会话及关闭回调，再打开独立 Screen；菜单动作在预览中被替换为空回调，
不需要为编辑器放宽任何服务端权限。
